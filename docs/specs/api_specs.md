
# **API SPECIFICATION**

## 1. General Rules
*   **Base Path:** `/api/v1`
*   **Authentication:** JWT via the header `Authorization: Bearer <accessToken>`. 
*   **Identity:** `studentId`/`userId` must be extracted from the JWT, and **must never** be taken from the request body/path parameters to decide data ownership.
*   **Time format:** ISO 8601 with timezone (e.g. `2026-11-01T08:00:00+07:00`).

## 2. Roles & Permissions
*   `Public`: No token required.
*   `Authenticated`: Requires a valid JWT (any role).
*   `STUDENT`: Students browse, register for and drop classes.
*   `SYSTEM_ADMIN`: Administrators create classes and open/close the registration period.

---

## 3. Endpoints & Payloads

### 3.1. Authentication & Users
| Method | Endpoint | Auth | Purpose |
| :--- | :--- | :--- | :--- |
| `POST` | `/auth/login` | Public | Log in (Email/Student code). |
| `POST` | `/auth/refresh-token` | Public | Issue a new access token. |
| `GET` | `/users/me` | Auth | Get the current user's profile. |
| `PUT` | `/users/me/password` | Auth | Change the current user's password. |

**Payload `POST /auth/login`:**
*Request:*
```json
{
  "identifier": "student@example.edu",
  "password": "example-password"
}

```

*Response (200 OK):*

```json
{
  "accessToken": "<jwt-string>",
  "refreshToken": "<refresh-token-string>",
  "tokenType": "Bearer",
  "expiresIn": 900
}

```

*(Note: passwordHash is never returned in any response).*

### 3.2. Enrollment Period Configuration

Only **one shared registration period** is supported in the system. It cannot be changed while the period is open.

| Method | Endpoint | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/enrollment-periods/current` | Public | View the registration period's status/time window. |
| `PUT` | `/enrollment-periods/current` | ADMIN | Update the open/close time. |

**Payload `PUT /enrollment-periods/current`:**
*Request:*

```json
{
  "startAt": "2026-11-01T08:00:00+07:00",
  "endAt": "2026-11-03T17:00:00+07:00"
}

```

### 3.3. Course Classes

`classId` is generated by the system. `availableSeats` is computed in real time from the DB, not a static reserved-seat value.

| Method | Endpoint | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/course-classes` | Public | List classes (with pagination/filter). |
| `GET` | `/course-classes/{classId}` | Public | Class details (capacity, seats left). |
| `POST` | `/course-classes` | ADMIN | Create a new class (only before the registration period opens). |

**Payload `POST /course-classes`:**
*Request:*

```json
{
  "name": "Databases - Group 01",
  "credits": 3,
  "capacity": 60,
  "schedule": [
    { "dayOfWeek": 2, "shift": 1 },
    { "dayOfWeek": 4, "shift": 1 }
  ]
}

```

*Response (201 Created):*

```json
{
  "classId": "CLS-12345",
  "name": "Databases - Group 01",
  "credits": 3,
  "capacity": 60,
  "enrolledCount": 0,
  "availableSeats": 60,
  "schedule": [
    { "dayOfWeek": 2, "shift": 1 },
    { "dayOfWeek": 4, "shift": 1 }
  ]
}

```

### 3.4. Enrollments

Each class in the request list is processed independently. A failed class does not roll back a successful one.

| Method | Endpoint | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/enrollments` | STUDENT | Register for 1 or more classes (Batch). |
| `DELETE` | `/enrollments/{classId}` | STUDENT | Drop a class (releases the seat). |
| `GET` | `/enrollments/my-classes` | STUDENT | View the list of successfully registered classes. |

**Payload `POST /enrollments`:**
*Request:*

```json
{
  "classIds": ["CLS-101", "CLS-205", "CLS-307"]
}

```

*Validation rules (checked by the backend for each class):*

1. The registration period is open.
2. The class exists & `availableSeats > 0` (prevents overbooking).
3. No schedule conflict with classes already `ENROLLED`.
4. Total credits $\le$ the limit configured in the system.
5. The student has not already registered for this class (prevents duplicates).

*Response (200 OK):*

```json
{
  "results": [
    {
      "classId": "CLS-101",
      "status": "ENROLLED",
      "reason": null
    },
    {
      "classId": "CLS-205",
      "status": "REJECTED",
      "reason": "CLASS_FULL"
    },
    {
      "classId": "CLS-307",
      "status": "RETRY",
      "reason": "SYSTEM_BUSY"
    }
  ]
}

```

*(Status enum: `ENROLLED`, `REJECTED`, `RETRY`. Reason enum: `CLASS_FULL`, `SCHEDULE_CONFLICT`, `CREDIT_LIMIT_EXCEEDED`, `ALREADY_ENROLLED`, `ENROLLMENT_PERIOD_CLOSED`, `CLASS_NOT_FOUND`, `SYSTEM_BUSY`)*

**Payload `GET /enrollments/my-classes`:**
*Response (200 OK):*

```json
{
  "items": [
    {
      "classId": "CLS-101",
      "name": "Databases - Group 01",
      "credits": 3,
      "status": "ENROLLED"
    }
  ],
  "totalCredits": 3
}

```

*(Use this endpoint to confirm the status if the client's `POST /enrollments` request timed out).*

## 4. Error Standardization & Technical Constraints

### 4.1. HTTP Status & Error Object

*Common error response (4xx, 5xx):*

```json
{
  "code": "CLASS_FULL",
  "message": "The class is full.",
  "retryable": false
}

```

| HTTP | Description |
| --- | --- |
| `200` | OK. For `POST /enrollments`, returns 200 with the per-class result list (even if some classes are REJECTED). |
| `201` | Resource created successfully. |
| `400` | Bad Request (wrong schema, input validation failure). |
| `401` | Unauthorized (missing/invalid JWT). |
| `403` | Forbidden (wrong role). |
| `404` | Not Found. |
| `409` | Conflict (state conflict). |
| `503` | Service Unavailable (overload; the client handles Retry/Exponential Backoff). |

### 4.2. ACID & Concurrency Constraints (Mandatory)

1. **Prevent overbooking:** Handle contention (race conditions) strictly using DB locking or a message queue. The number of `ENROLLED` must never exceed `capacity`.
2. **Commit first, respond after:** The `ENROLLED` status may only be returned once the transaction has been successfully committed to the DB.
3. **Idempotency:** Retrying a registration request multiple times must not create junk data or record two registrations for one class.
4. **Graceful Degradation:** Under excessive load, the API must actively shed requests and return `503 Service Unavailable` instead of hanging requests and crashing the DB.
